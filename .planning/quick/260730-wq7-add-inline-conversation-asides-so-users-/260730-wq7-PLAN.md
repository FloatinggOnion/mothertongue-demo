<objective>
Add inline conversation asides to the roleplay drill and harden scenario prompts against role drift.

Purpose: A learner mid-scenario often needs a quick meta question ("wait, how do I say tomato?"). Today that question becomes a roleplay turn, derails the scene, and permanently pollutes `conversationHistory`. Separately, over longer conversations the partner model drifts and starts speaking as the user's character (becoming the buyer instead of the seller).

Output: Aside classification + answer service, discriminated `/api/chat` response, aside-tagged messages excluded from all LLM history payloads, a distinct inline aside bubble, an explicit Ask button, hardened partner system prompt, and a cheap post-generation drift self-check with one retry.

Out of scope: `mothertongue_app` (Flutter) — its drill screen is a fully mocked stub with no real API calls.
</objective>

Two layers, both required by CONTEXT decision "Role-drift fix".

**Layer 1 — prompt hardening in `buildPartnerSystemPrompt`.** Replace the single "Stay 100% in character" line with a dedicated, explicitly-labelled `ROLE BOUNDARY (ABSOLUTE)` block placed *before* the existing behaviour rules. It must state, referencing `${scenario?.aiRole}` by name:
   - You are ONLY ${aiRole}. The human user is the *other* party in this scene; you are never that person.
   - Produce exactly ONE utterance, spoken by ${aiRole}, and then stop.
   - Never write the user's lines, never prefix any speaker label or name-colon to your output, never write narration, stage directions, or actions for the user, never invent or predict what the user said or will say, never continue the exchange past your own turn.
   - If the user's meaning is unclear, ask one short in-character clarifying question rather than supplying their line for them.
   Keep the existing level-specific constraints and the `{ "reply": "..." }` JSON output contract unchanged.

   Add periodic reinforcement without redesigning the call: in `getPartnerResponse`, when `conversationHistory.length >= 6`, insert an extra `{ role: 'system', content: ROLE_REINFORCEMENT }` message immediately *before* the final `{ role: 'user', content: userMessage }` entry. `ROLE_REINFORCEMENT` is a module-level template producing a one-line reminder naming ${aiRole} and repeating the "never speak for the user, one utterance only" rule. Recency is the point — a system line adjacent to the newest turn survives long histories better than the far-away opening prompt.

**Layer 2 — runtime self-check.** Add:

   `export async function detectRoleDrift(reply: string, scenario: any, historyLength: number): Promise<boolean>`
   - Stage 1 heuristic (free, always runs): module-level `DRIFT_PATTERNS` matching speaker labels at line start (`/^\s*(user|you|me|customer|buyer|student|learner)\s*:/im`), any line-start `Name:` label including the scenario's own `aiRole` first word, bracketed or asterisked stage directions referencing the user (`/\*[^*]*\b(you|the user|the customer)\b[^*]*\*/i`, `/\[[^\]]*\byou\b[^\]]*\]/i`), and the presence of 2+ line-start speaker labels. Any match returns `true` with no network call.
   - Stage 2 (only when heuristic is clean AND `historyLength >= 6` — drift emerges over longer conversations, so paying for a check on every short exchange is waste): one `callGroq` with `{ json: true, temperature: 0 }` asking whether the reply is voicing the user's side rather than speaking as ${aiRole}; expect `{"voicedUser": boolean}`. Any throw or unparsable response returns `false` (never block a valid reply on a failed check).

   Wire into `getPartnerResponse`: after parsing `reply` from the first generation, call `detectRoleDrift`. If true, regenerate **once** with a corrective `{ role: 'system' }` message appended after the original system prompt stating that the previous attempt broke the role boundary by speaking for the user and that this attempt must contain only ${aiRole}'s single utterance. Use the retried reply unconditionally — no third attempt, no recursion. Translate only the final chosen reply (do not translate a discarded draft). Preserve the existing try/catch fallback reply behaviour and the existing return shape `{ reply, translation }`.

Keep `console.error` for diagnostics, consistent with the rest of the file.
